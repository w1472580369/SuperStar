# v3.3.3 — Session isolation and account binding

## Security and correctness fixes

- Bind every cached DeepSeek chat session to the account that created it. A
  continued conversation now preferentially reacquires that account; when it
  is busy or unavailable, the proxy starts a fresh session instead of sending
  its session ID and parent chain with another account's credentials.
- Scope cached conversations to the calling API key (stored only as a hash),
  or to the client IP when unauthenticated.
- Support OpenAI's top-level `user` field as an explicit session identifier.
- Remove the unsafe first-message-hash fallback. Requests without
  `X-Conversation-Id`, OpenAI `user`, or Anthropic `metadata.user_id` now use
  a fresh upstream session.

## Tests and automation

- Add regression coverage for account-bound reuse, account selection, caller
  isolation, and OpenAI `user` handling.
- Add a tag-triggered GitHub Actions release workflow.

# v2.2.0 — Production hardening, multi-turn sessions, model routing, client rate limiting, unit + e2e CI

> 2026-06-25 · 7 commits since v1.1.0 · supersedes the (now-retracted) v2.0.0 cut

This is the recommended release for production deployments. It
**includes every commit from the retracted v2.0.0 cut** (the four
anti-detection / hardening PRs from **@nianshou**) **plus** the
follow-up production hardening, new features, and test matrix that
landed on `main` after v2.0.0 was tagged.

If you have not deployed before, **start here**.

## Highlights

### v2.0.0 baseline (anti-detection & admin hardening) — by **@nianshou**

- **TLS / JA3 impersonation** against chat.deepseek.com via
  `curl_cffi` (chrome131 profile) — DeepSeek's WAF no longer rejects
  handshakes from clients that look nothing like a real browser.
- **Real-Chrome request headers + token wrapper unwrapping** — the
  adapter now sends a complete set of `sec-ch-*` / `sec-fetch-*` /
  `priority` / `x-client-bundle-id` headers captured from a live
  Chrome 131 session, and accepts DeepSeek's localStorage JSON
  wrapper (`{"value":"…","__version":"0"}`) in addition to the bare
  token.
- **WebUI path-traversal fixed** — unauthenticated reads of `.env` /
  `data/accounts.json` via `/webui/..%2F.env` are no longer possible.
- **Admin API hardened** — constant-time password compare, per-IP
  sliding-window login throttle (5 fails / 300 s), and a working
  `/admin/api/logout` that revokes the bearer token.
- **CI smoke test** runs on every push to `main`.

### v2.2.0 — production hardening (this release's new work)

- **Safe-by-default bind** — `HOST=127.0.0.1`. The server refuses to
  start on a public bind (`0.0.0.0`) with the default admin password
  unless `ALLOW_INSECURE_PUBLIC_DEFAULTS=true` is set explicitly.
- **At-rest credential encryption** — set `DEEPSEEK_ENCRYPTION_KEY`
  (Fernet) and `data/accounts.json` is encrypted with AES-128-CBC +
  HMAC. Existing plaintext files are transparently migrated on first
  startup; the original is preserved as `accounts.json.v1.bak`.
- **CORS allow-list** — `ALLOWED_ORIGINS` replaces the spec-violating
  `allow_origins=["*"]` + `allow_credentials=True`. Default is
  same-origin only.
- **XFF whitelist** — `TRUSTED_PROXIES` ensures
  `X-Forwarded-For` is only trusted when the immediate peer is in
  the configured CIDR list (admin login throttle can no longer be
  bypassed by spoofing a header).
- **Security response headers** — `X-Content-Type-Options`,
  `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` on every
  response, with an extra `Content-Security-Policy` on `/webui`.
- **Structured JSON logging** — `LOG_FORMAT=json` for production,
  `LOG_LEVEL` configurable. All `print(...)` and `except: pass` sites
  replaced with `logger.warning / .debug / .exception`.
- **Model routing** — `MODEL_ROUTES` JSON map switches the upstream
  `model_type` (quick / expert) and the default `thinking` /
  `search` per client `model` field. `/v1/models` enumerates every
  entry in the routing table.
- **Multi-turn conversations** — `SESSION_CACHE_TTL` (default 600 s)
  reuses a `chat_session_id` across requests when the client sends a
  stable identity (OpenAI `X-Conversation-Id` header, Anthropic
  `metadata.user_id`, or a hash of the first user message).
- **Client rate limiting** — per-API-key + per-IP sliding window
  (`CLIENT_RPM_PER_KEY` / `CLIENT_RPM_PER_IP`). 429 responses carry
  `X-RateLimit-*` and `Retry-After` headers.
- **Real `usage` field** — `usage.prompt_tokens` and
  `usage.completion_tokens` are real counts (tiktoken `cl100k_base`,
  character-heuristic fallback). No more hard-coded `-1`.
- **P50 / P95 / P99 latency + success rate** in `/admin/api/stats`.
- **Bug fix: Anthropic non-streaming `thinking` was being dropped.**
  `adapter.chat()` now returns `(content, thinking)`; the
  `/v1/messages` non-stream response includes a real
  `{"type":"thinking","thinking":"…"}` content block.
- **Bug fix: account error state auto-recovers.** After 3 consecutive
  failures, a background `check_health` clears the `error` flag if
  the upstream is reachable again (e.g. WAF challenge window
  expired).
- **StreamSieve boundary fixes** — iterative drain (no more
  `self.feed("")` recursion), 1 MiB capture-buffer cap (configurable
  via `DSML_MAX_BUFFER_BYTES`), edge cases on bare `<` and
  unclosed DSML tags.
- **OpenAI streaming error frame** — exceptions during a stream now
  yield `data: {"error":{…}}` + `data: [DONE]` instead of bubbling
  up a 500 mid-stream.
- **CI matrix** — `tests/smoke.py` (Python 3.12), `pytest` unit
  suite (3.10 / 3.11 / 3.12), and a 3-scenario end-to-end harness
  (`scripts/run_e2e.py`) covering functional surface + startup
  refusal + startup bypass.
- **`start.bat` hardened** — only kills processes whose command line
  contains `uvicorn` / `server.py` / `ds2api`; never blindly
  `taskkill /F` whatever happens to hold the port.

## Detailed changes

### 1. TLS / JA3 impersonation — `4b790ea` · **@nianshou** (nianshou555qiansui)

Replaces the plain `httpx` transport in `DeepSeekAdapter` with a
`curl_cffi.Session(impersonate="chrome131", timeout=120)`. The
chrome131 profile negotiates a ClientHello that matches the JA3
fingerprint of a real Chrome 131 build, which is what chat.deepseek.com
expects.

- New runtime dependency: `curl_cffi>=0.7.1`.
- Account-level proxy support: `DEEPSEEK_PROXY` / `DEEPSEEK_PROXY_N`
  pin a single account to a residential exit so multi-account
  deployments don't all look like they come from the same data center.
- Inter-call jitter (`DEEPSEEK_JITTER_SECS`, default 0) — sleep a small
  uniform-random delay before each PoW request to break perfectly-timed
  automation patterns.
- `DEEPSEEK_IMPERSONATE` lets the operator switch profiles
  (`chrome120` … `chrome136`); the captured UA in `_DEFAULT_UA` is
  pinned to Chrome 131 to match what `curl_cffi` actually negotiates.

### 2. Real-Chrome request headers + token wrapper unwrapping — `088ac1e` · **@nianshou**

The previous `_base_headers` in `adapter.py` had a truncated UA, no
`sec-ch-*` / `sec-fetch-*` / `priority` headers, a frozen
`X-App-Version: 20241129.1` (six months stale at the time of
release), and no `x-client-bundle-id`. All of these were fingerprintable
by DeepSeek's risk engine as non-browser traffic.

This commit replaces the headers with values captured from a live
Chrome 131 + chat.deepseek.com session on 2026-06-19, and bumps
`X-App-Version` / `X-Client-Version` to `2.0.0` to match the current
client build.

A new `DeepSeekAdapter._normalize_token()` accepts both the bare
token, a `Bearer <token>` form, and DeepSeek's localStorage JSON
wrapper (`{"value":"…","__version":"0"}`) — so users copying from
DevTools → Application → Local Storage get the same outcome as users
copying the `Authorization` header.

### 3. WebUI path-traversal fix — `d52181e` · **@nianshou**

The `/webui/{rest_of_path}` handler previously resolved user paths
with `os.path.join` + `os.path.isfile` but never checked that the
resolved file stayed inside the webui directory. An unauthenticated
caller could read `.env` and `data/accounts.json` via payloads like
`/webui/..%2F.env`.

The fix introduces `_safe_webui_path()` in `server.py`:

```python
def _safe_webui_path(rest_of_path: str) -> str | None:
    if not rest_of_path or "\x00" in rest_of_path:
        return None
    candidate = os.path.realpath(os.path.join(_WEBUI_DIR, rest_of_path))
    try:
        common = os.path.commonpath([candidate, _WEBUI_DIR])
    except ValueError:
        return None
    if common != _WEBUI_DIR:
        return None
    if not os.path.isfile(candidate):
        return None
    return candidate
```

The handler falls back to `index.html` (SPA shell) on a traversal
attempt, so the route is still usable as a catch-all without leaking
files. The smoke test asserts 6 distinct traversal payloads are
rejected.

### 4. Admin API hardening — `d5b8c3a` · **@nianshou**

- `secrets.compare_digest` replaces the bare `==` comparison in both
  `_verify_token` and the login handler — eliminates a
  microsecond-scale timing oracle that an attacker could exploit to
  brute-force admin passwords.
- Per-IP sliding-window throttle on `/admin/api/login`: 5 failures
  per 300 seconds (configurable via `_LOGIN_MAX` / `_LOGIN_WINDOW`).
  After the cap is hit the endpoint returns 429.
- New `POST /admin/api/logout` revokes the bearer token in the
  `Authorization` header. Previously tokens were only invalidated by
  process restart.

## Upgrade notes

- `requirements.txt` now requires `curl_cffi>=0.7.1`, `cryptography>=42`,
  `tiktoken>=0.7`, `httpx>=0.27`, `httpx2>=2.0`. Re-run
  `pip install -r requirements.txt` after pulling.
- The default `X-App-Version` header bumped from `20241129.1` to
  `2.0.0`. If a downstream service filters on this header, update
  its allowlist.
- The bind address default moved from `0.0.0.0` to `127.0.0.1`. To
  keep the old behaviour (e.g. when running behind a reverse proxy
  that already enforces auth) set `HOST=0.0.0.0` and either change
  `DEEPSEEK_ADMIN_PASSWORD` to something strong or set
  `ALLOW_INSECURE_PUBLIC_DEFAULTS=true`.
- Existing `data/accounts.json` is automatically migrated to the
  encrypted v2 format on first startup when
  `DEEPSEEK_ENCRYPTION_KEY` is set. The plaintext original is
  preserved as `accounts.json.v1.bak`; you can delete it after
  verifying the migration.
- No breaking changes to the public API surface — clients do not
  need to be updated.

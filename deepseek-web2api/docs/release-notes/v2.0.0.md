# v2.0.0 — Anti-detection TLS impersonation, admin hardening, webui path-traversal fix

> 2026-06-25 · 6 commits since v1.1.0 · 4 PRs from `nianshou` + 1 CI PR from the maintainer

This release marks the first production-grade cut of the DeepSeek Chat API
proxy. It bundles the work that took the project from "works in dev" to
"safely usable behind a reverse proxy on a public network". All four
anti-detection / hardening PRs from **@nianshou** (commits on Jun 24,
2026) ship together with the smoke test / CI scaffolding.

> **v2.2.0** (released immediately after this tag) builds on top of
> `v2.0.0` and adds the production deployment hardening, model routing,
> multi-turn sessions, client rate limiting, and the unit + e2e test
> matrix. If you are deploying fresh, skip directly to **v2.2.0**.

---

## Highlights

- **TLS / JA3 impersonation** against chat.deepseek.com via `curl_cffi`
  (chrome131 profile) — DeepSeek's WAF no longer rejects handshakes
  from clients that look nothing like a real browser.
- **Real-Chrome request headers + token wrapper unwrapping** — the
  adapter now sends a complete set of `sec-ch-*` / `sec-fetch-*` /
  `priority` / `x-client-bundle-id` headers captured from a live
  Chrome 131 session, and accepts DeepSeek's localStorage JSON wrapper
  (`{"value":"…","__version":"0"}`) in addition to the bare token.
- **`/admin/api/login` hardened** with constant-time password compare,
  per-IP sliding-window throttle, and a working `/admin/api/logout`.
- **WebUI path-traversal fixed** — unauthenticated reads of `.env` /
  `data/accounts.json` via `/webui/..%2F.env` are no longer possible.
- **CI smoke test** runs on every push to `main` via GitHub Actions,
  with 7 check groups that cover the high-risk paths (auth, traversal,
  static serving).

## Detailed changes

### 1. TLS / JA3 impersonation — `4b790ea` · @nianshou555qiansui

Replaces the plain `httpx` transport in `DeepSeekAdapter` with a
`curl_cffi.Session(impersonate="chrome131", timeout=120)`. The
chrome131 profile negotiates a ClientHello that matches the JA3
fingerprint of a real Chrome 131 build, which is what chat.deepseek.com
expects.

- New runtime dependency: `curl_cffi>=0.7.0`.
- Account-level proxy support: `DEEPSEEK_PROXY` / `DEEPSEEK_PROXY_N`
  pin a single account to a residential exit so multi-account
  deployments don't all look like they come from the same data center.
- Inter-call jitter (`DEEPSEEK_JITTER_SECS`, default 0) — sleep a small
  uniform-random delay before each PoW request to break perfectly-timed
  automation patterns.
- `DEEPSEEK_IMPERSONATE` lets the operator switch profiles
  (`chrome120` … `chrome136`); the captured UA in `_DEFAULT_UA` is
  pinned to Chrome 131 to match what `curl_cffi` actually negotiates.

### 2. Real-Chrome request headers + token wrapper unwrapping — `088ac1e` · @nianshou

The previous `_base_headers` in `adapter.py` had a truncated UA, no
`sec-ch-*` / `sec-fetch-*` / `priority` headers, a frozen
`X-App-Version: 20241129.1` (six months stale at the time of
release), and no `x-client-bundle-id`. All of these were fingerprintable
by DeepSeek's risk engine as non-browser traffic.

This commit replaces the headers with values captured from a live
Chrome 131 + chat.deepseek.com session on 2026-06-19, and bumps
`X-App-Version` / `X-Client-Version` to `2.0.0` to match the current
client build.

A new `DeepSeekAdapter._normalize_token()` accepts both the bare
token, a `Bearer <token>` form, and DeepSeek's localStorage JSON
wrapper (`{"value":"…","__version":"0"}`) — so users copying from
DevTools → Application → Local Storage get the same outcome as users
copying the `Authorization` header.

### 3. WebUI path-traversal fix — `d52181e` · @nianshou

The `/webui/{rest_of_path}` handler previously resolved user paths
with `os.path.join` + `os.path.isfile` but never checked that the
resolved file stayed inside the webui directory. An unauthenticated
caller could read `.env` and `data/accounts.json` via payloads like
`/webui/..%2F.env`.

The fix introduces `_safe_webui_path()` in `server.py`:

```python
def _safe_webui_path(rest_of_path: str) -> str | None:
    if not rest_of_path or "\x00" in rest_of_path:
        return None
    candidate = os.path.realpath(os.path.join(_WEBUI_DIR, rest_of_path))
    try:
        common = os.path.commonpath([candidate, _WEBUI_DIR])
    except ValueError:
        return None
    if common != _WEBUI_DIR:
        return None
    if not os.path.isfile(candidate):
        return None
    return candidate
```

The handler falls back to `index.html` (SPA shell) on a traversal
attempt, so the route is still usable as a catch-all without leaking
files. The smoke test asserts 6 distinct traversal payloads are
rejected.

### 4. Admin API hardening — `d5b8c3a` · @nianshou

- `secrets.compare_digest` replaces the bare `==` comparison in both
  `_verify_token` and the login handler — eliminates a
  microsecond-scale timing oracle that an attacker could exploit to
  brute-force admin passwords.
- Per-IP sliding-window throttle on `/admin/api/login`: 5 failures
  per 300 seconds (configurable via `_LOGIN_MAX` / `_LOGIN_WINDOW`).
  After the cap is hit the endpoint returns 429.
- New `POST /admin/api/logout` revokes the bearer token in the
  `Authorization` header. Previously tokens were only invalidated by
  process restart.

### 5. CI smoke test — `0cb9abc` · snake-aabb-wtf

`tests/smoke.py` (in-tree, no extra dependencies) plus
`.github/workflows/ci.yml` so every push to `main` boots the whole
app graph, hits `/health`, the WebUI shell, six path-traversal
payloads, the admin auth flow (correct + wrong password, missing
header, expired token), and the adapter's token normalization helper.

The smoke test runs without real DeepSeek credentials and without
network access — it is suitable for any runner.

## Upgrade notes

- `requirements.txt` now requires `curl_cffi>=0.7.0`; if you previously
  pinned `httpx` you can leave it (some transitive code still uses it).
- The default `X-App-Version` header bumped from `20241129.1` to
  `2.0.0`. If you have a downstream service that filters on this
  header, update its allowlist.
- No breaking changes to the public API surface — clients do not need
  to be updated.
